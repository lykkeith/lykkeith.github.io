Privacy Policy

This policy describes the existing account connection and the planned Google Docs workflows of ACC Creative Actions, the operator-managed application for Anatomy of Interobjectivity: The Algorithmic Flesh.

Operator and contact

The ACC installation is managed by Keith. Questions about access, stored data, correction or deletion can be sent to lamyankitkeith@gmail.com. These requests are handled by the operator; there is no automated self-service deletion portal.

Data accessed

The connection uses only Google’s drive.file scope. It can access files created through the app or deliberately selected for the app, subject to the account’s actual file permissions. It does not request full-Drive, Gmail or Contacts access.

  • Account identity: the Google account email address and Drive permission identifier used to verify the connected identity.
  • Authorization credentials: access and refresh tokens, client binding and expiry metadata needed to maintain an authorized connection.
  • For separately approved document workflows: selected document content, title, file identifier, revision information, relevant contributor or permission information, and action/readback records needed to save or revise the correct work and resolve conflicts.

At the current account-preparation stage, authorization and identity verification have been performed. This batch has not created or read document bodies, or created or modified a document.

Purpose and processing

Account data is used to verify the correct agent identity and maintain that account’s authorized connection. Document data, when separately enabled, is used for the approved writing or collaborative revision workflow and its version, provenance, conflict-resolution and completion records.

Authorized source material may be processed by the installation’s agent workflow for the selected writing task. This can include model inference on explicitly approved installation hosts; it is not authorization to train a general-purpose or shared model. No such model processing is enabled by the account-authorization preparation itself.

The intended use excludes advertising, selling or brokering Google user data, or using that data to train a general-purpose or shared model. Google has not yet completed any required production verification for this installation; authorization and live document acceptance remain separate steps.

Storage and access

At this stage, credentials remain on the operator’s M1 Mac: tokens use device-only macOS Keychain entries, and the Desktop client file is kept in a restricted local directory. Receipts contain identity, permission, expiry and provenance metadata rather than raw tokens. Authorized local work and provenance records may also retain document data when document workflows are enabled.

Credentials have not been provisioned to the installation’s M2 machines by this work. Any future deployment must have separate operator approval, an accurate host/storage disclosure and an updated policy before a materially different use of Google data. A token without a reported expiry is not treated as permanently valid.

The operator can access local records for the approved workflow and support. This app does not ask users to paste passwords or tokens into a chat.

Disclosure and publication

Google processes the authorization and Google API requests under its own policies. This application does not automatically publish Google document contents or make them available to exhibition visitors. Sharing or exporting a selected work to collaborators or another platform requires a separate, exact authorization and a disclosure appropriate to that action; Google consent alone is insufficient. Any platform receiving a separately approved work also processes it under that platform’s policies.

Retention and deletion requests

No automatic end-of-exhibition deletion schedule is currently configured. Credentials and local archives may remain after the exhibition until the operator carries out an approved revocation or retention review. Do not assume that the exhibition end date deletes Google files or local records.

Contact the operator to request review, export, correction or deletion of local data. Some provenance records are append-only, so changes or deletion require an explicit review rather than silent alteration of an agent’s history. There is no automatic deletion capability or fixed response deadline currently implemented.

Revoking access

You can revoke the app’s Google access through Google Account third-party connections. The prepared credential handler is designed to stop that identity’s Google effects when a refresh is rejected as invalid_grant; its production integration is not yet enabled. Reauthorization requires operator involvement. Revocation does not itself delete previously created Google files, previously retained local records or separately published material. Contact the operator about those records.

This information site

The supplied pages contain no forms, app analytics, tracking scripts, remote fonts or app-set cookies. This information site is intended to be hosted on GitHub Pages. GitHub records visitors’ IP addresses for security purposes, including visitors who are not signed in. GitHub handles those records under its Privacy Statement; ACC does not specify or promise a separate retention period for GitHub’s security logs. This site does not ask visitors to authorize a Google account.

Changes

Material changes to data access, use, storage or sharing must be disclosed before that new use, with renewed consent where required. Last updated: 1 November 2026.
